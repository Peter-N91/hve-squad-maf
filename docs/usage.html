The contract, not a capability wishlist

One runtime, one project

  1. Create

    SquadRuntime.CreateAsync(IChatClient, SquadRuntimeOptions, SquadArtifactSource?, CancellationToken) snapshots options, resolves artifacts, loads the release catalog, validates the roster, and checks existing state. It does not own your chat client's lifetime.

  2. Confirm initialization and routing

    The host confirms single-squad scope, profile/packs, roster, names, and channel before squad state or model calls are created. Routing approval confirms scope, producing owner, all input paths, and council/RAI coverage. Model classification is a proposal, not authorization.

  3. Execute the bounded workflow

    Eligible goals may start with human-confirmed discovery and an analyst brief. Intake independently validates existing or newly discovered inputs, reuses unchanged readiness and allows at most two shrinking-gap supplemental-draft cycles. Research and verified planning precede a task-fit parallel council, plan-derived producing owners and independent review. The current release uses one structurally verified plan; recognized legacy resources retain linked phase details. Interactive mode confirms stages and consequential calls. Other modes waive only routine confirmations and explicitly host-classified safe work, never a specific mandatory gate.

  4. Inspect the result and dispose

    Read status and verified evidence, not just response prose. Await the active run before disposing the runtime. Retain the original release and roster to continue its project-bound sessions.

Select the release's actual roster

Profiles and packs come from the released squad-roster.instructions.md and canonical references/roster-catalog.md, not an embedded role map. The following names are from the exercised v0.18.1 catalog. The inspector prints the catalog for the release you actually acquire.

GetInitializationChoices(request) performs bounded read-only project discovery and offers canonical profiles, packs, custom role descriptions, missing-resource prerequisites, single-squad/federation topology, naming policies and optional notification contacts. SelectInitializationAsync can return a changed proposal; ApproveAsync confirms the exact selection before any state is written. A federation choice returns an explicit ApprovalRequired handoff to SquadFederation.InitializeAsync with required named members, never a silently seeded single squad.

The existing DI factory also exposes CreateFederationAsync(). The controller supports confirmed Init/Promotion/Expansion, ordinary member runtimes and actual dependency-ordered RunAsync(request, configuration). Typed Members/Dependencies produce a confirmed script; an explicit Target stays forward-only. ResumeAsync(metaRunId), pending/submit/poll/renew, scoped ReviseMemberAsync and effect/evidence/billing reconciliation preserve original authority. ResumeLifecycleAsync(operationId) is separate and resumes only a confirmed file transaction. See the working federation API for exact handoff, aggregate cost and final-human contracts.

Roles selects a custom subset and AdditionalRoles adds explicitly accepted roles, including council extensions. Scribe is always included. The methodology spine is recommended, not forced into a custom roster; a later missing research/plan/produce/review leg blocks. UpdateRosterAsync(configuration) has its own RosterUpdate approval and retains surviving names, approved roots, prior output bytes and append-only history. Pack removal retains any role still contributed by the profile or another pack; removed-member spend remains marked in consumption. RosterConfiguration returns a defensive settings copy.

Concrete routing and model policy

Routing uses the canonical intent rules and confirmed roster. A specific contained phrase, such as test plan, owns its generic plan match. Disjoint competing outcomes require a human owner choice, not a longest-keyword guess. Off-roster and escalation-only matches do not dispatch a substitute. Primaries remain the default; a justified canonical Selection Cue may select a concrete alternate, with its rationale recorded.

GetModelRoutingChoicesAsync() is state-read-only. UpdateModelRoutingAsync(configuration) changes a confirmed policy without resetting outputs/history. Off omits routing overrides and keeps the existing host selector/provider ownership; map charter preferences through your host selector rather than assuming Copilot pins are runnable on a generic IChatClient. Ranked and manual use only actual host-advertised client bindings and the installed catalog's assignment fit, cost ordering and fast/default/extended floors. Native Scribe work has no model.

Manual selection supports suggested models, assignment-class choices at the highest applicable floor, and individual exceptions. Each model menu has at most eight best-ranked choices; any other exact advertised ID can be typed and validated. Uncatalogued IDs are explicit manual-only and unevaluated; they need an exact host tariff to be priced. Missing or refused manual cells ask before that role dispatches; unanswered input suspends rather than choosing silently.

A specific pre-execution SquadModelUnavailableException narrows this run's available set and permits floor-safe reranking. Manual substitution asks again. Ordinary failures and a rejection after actual tool execution never retry. History records Requested model, Effective model, Observed model and Route rationale separately. Concrete mismatches reach the run summary; a known below-floor response blocks before tool execution. Unreported/unverified identity is not a mismatch. Routing and cost admission do not guarantee live-model answer quality.

Exact model-spend admission

SquadConsumptionConfiguration uses exact provider model IDs, a verified date/source and estimator revision 2. Every SquadModelRate.Standard has Input, Cached, CacheWrite and Output USD-per-million rates. Confirm a flat tariff with FlatRateConfirmed, or supply a positive LongContextThresholdTokens and all four LongContext rates. Ranking's Blended price is not a billing tariff. Rates exactly 90 days old are current; older or future-dated rates cannot admit a ceiling.

Real provider attempts include coordinator, failed/rejected work and retired members. Observed identity takes precedence over the effective passed ID; requested aliases and tiers never become price identities. Missing historical tariff snapshots stay unpriced. Missing token telemetry has a labeled conservative class-floor estimate per attempt; native Scribe work has no model tokens. SquadRunResult.Consumption separates known subtotals from unknown totals and unobserved historical dispatches.

Calibration requires positive observations, a real last-reconciled date and the exact ObservedOn|2 basis. First run without a ceiling and obtain an authorized actual billing delta. ReconcileConsumptionAsync confirms that observation, rejects unknown or different-tariff denominators and updates a mean clamped to 0.25–10.0 once per run. Reusing the same host tariff template preserves reconciliation across runtime instances; changed tariffs invalidate old calibration. Historical charges are never multiplied again.

var baseline = await squad.RunAsync("Research a bounded calibration case.");
await squad.ReconcileConsumptionAsync(new SquadConsumptionReconciliation(
    baseline.RunId, observedModelCostUsd, "host-billing-receipt"), cancellationToken);

    new SquadRunConfiguration("10.00"), cancellationToken);

Configure the actual client/model and verified tariff before creating squad. observedModelCostUsd is your host's actual billing observation, never an invented value. The sample accepts JSON consumption data and --cost-ceiling; its console shows exact cost approvals.

Admission reserves the complete current mode boundary, pre-plan owners, declared workers and maximum intake remediation. Calibration applies once; unrounded rows are summed, multiplied by a 3.0 reserve and only totals round to four decimals. Confident equality admits. cannot-confirm and spend at/above the ceiling cannot be approved. CostOvershoot permits sequential unchanged-demand units only; changed pricing, context, identity, ceiling or expanded demand opens a new gate. An in-flight unit completes its handoff; no later substantive unit starts after terminal spend. Pending handoffs reserve admitted raw cost × 3.0 until verified recorded spend replaces it once.

CostPreflight records the run, round, exact demand and permitted slots before work. Stale or partial snapshots fail compare-and-swap without overwriting preserved bytes. Fan-out, autonomous/autopilot and authenticated durable cost approval use the same authority, including both possible validation cycles and final validation. Safe pipelining reserves pending projection times 3.0 once; approved overshoot stays sequential. Federation remains unavailable. These figures estimate model spend, not invoices or Azure workload budgets.

Delegate flow without delegating permission

interactive keeps the existing stage and consequential-call approvals. autonomous selects task-fit independent council seats, implements a permitting verdict and revalidates actual output at most twice. Conditions must remain outstanding or be checked through ResolvedConditions with exact produced evidence. A satisfied conditional verdict can converge. Cycle two always reaches a human AutonomousOutcome gate, even if converged; there is no third cycle.

autopilot requires a producing outcome and runs applicable discovery/intake, research, plan, task-fit council, real plan-owned producing waves, bounded validation, independent review and exact FinalOutcome human validation. Routine routing/planning/implementation confirmations flow automatically. Initialization, discovery direction, roster/model decisions and specific risk, cost and impactful actions retain their own gates. A final approval never deploys, pushes, merges or authorizes an unrelated future action.

Any Stop, high-risk finding, material human fact, confirm-tier cost move, compliance violation or stable issue divergence fires RiskGate. Acknowledgement of a Stop is not permission to implement. Unknown costs and below-floor identity remain non-admitting. Only trusted code can set SquadToolRegistration.Impact/Action; an omitted impact is gated. Safe permits bounded attested local writes or explicitly safe retrieval, never external mutations. Deployment, push, merge, migration, deletion, rotation, compliance, cost confirmation and irreversible action classifications always retain their exact gates, even if marked safe.

A second independently requested draft may revise only its own producing unit's prior output. Before execution, the Scribe archives the exact original bytes with a validation-bound immutable receipt. Authenticated final fan-out changes may reopen the unchanged plan's units and dependency handoffs with the exact human-change receipt as authority. Other units still cannot overwrite or borrow effects. Single-build final /changes after one validation reopens the second draft and requires fresh cap/final decisions; changes after the second producing iteration create a new human risk stop, never a reset.

With actual native parallel dispatch capability (MaxConcurrentDispatches > 1), autopilot overlaps safe research-to-plan and plan-to-council calls with one Scribe handoff. Cost rounds run outside that overlap; all consuming gate/effect/revalidation/review/final barriers drain and verify history. Ledger-only warnings do not disable it; a pipelined history-integrity failure latches it off and blocks dependent work. ModeOutcome reports actual cycles, convergence, final human validation and verified overlaps. Mode summaries refer to actual per-agent history records, not stage narratives.

The live sample accepts --mode interactive|autonomous|autopilot or JSON mode. Its bounded source writer is explicitly safe for noninteractive modes; interactive writes still prompt. Exact mode, classification, release, root and limits remain bound on restart. Durable final/cycle/risk gates use the same authenticated response APIs as other actions. Authorized Watch is a separate event entry point, not a mode flag: HandleWatchEventAsync, RegisterWatch and ReconcileWatchAsync reuse the original inner runtime and attributed gates. Its native runner accepts separate --watch-event/--watch-settings files, not control text. These APIs do not prove tenant authentication or business/model quality. Registered skill execution remains a separate code-only host capability.

Authenticated durable suspension

Register InChatApprovalChannel with the application's actual authenticated principal resolver and case/action rights check, or GitHubIssueApprovalChannel with a caller-owned authenticated HTTP client and confirmed repository/human account. Initialization and independent management operations retain their explicit callbacks. The library is transport-agnostic; it does not provision tenant authentication or a hosted server.

GetPendingHumanActionsAsync() and SquadRunResult.PendingHumanActions return safe opaque metadata. ReadHumanActionAsync(actionId) returns the exact private payload only to trusted host code; enforce case read access before exposing it. SubmitHumanResponseAsync(response) authenticates the real channel actor/source and persists the decision without model work or project effects. Explicit ResumeAsync(runId) continues the same run. GitHub hosts use one bounded PollHumanResponsesAsync(runId) to fetch and authenticate actual provider events, not untrusted webhook event text.

Every response binds root, release, host registration, run, gate, revision, dispatch, cost round, arguments and verified evidence. Stale, replayed, wrong-action, unauthorized or altered-payload responses fail closed. Private pending arguments, questions and human notes use protected payload references/digests; remote messages contain no case text, raw arguments or private artifact paths. /approve applies only to the unchanged action, /answer: text answers only its question, /changes: note reopens affected work with descriptive input and /stop freezes work before a stopped outcome is recorded on resume. Changed producing calls retain dispatch/effect identities and require fresh approval; uncertain effects still require trusted reconciliation.

GitHub comments and attributed squad/approved, squad/changes and squad/stop label events require the registered human or current write/maintain/admin collaborator. Bots, unrelated prose and blanket /approve-all are not consent. Provision squad-approval/squad/changes labels and Issues/account/collaborator permissions deliberately. Disable automatic redirects. Credentials remain in caller-owned HTTP authentication, never native state or notification payloads.

Revised readiness/council receipts get distinct identities, preserving all original verdict bytes. Returned intake questions require actual authenticated answers and independent revalidation within the existing two-cycle bound; an answer is not a readiness override. If submission was interrupted after its immutable receipt, answer/stop context is reconstructed only from that exact authenticated receipt, never from model text or a local approval file.

WebhookSquadNotifier resolves a host-owned secret HTTPS endpoint at send time and is outbound-only. Its actual delivery status is separate from approval; suppress/redact secret webhook URL telemetry in the host. HumanResponseTimeout defaults to one day; timeout is never approval. RenewHumanActionAsync(actionId) explicitly renews an expired unchanged challenge or reconciles its notification. An uncertain issue creation is looked up, never blindly repeated.

Make real effects explicit

Native tools read project files and write allocated methodology artifacts. They are not a general source editor. Register actual host capabilities through SquadToolRegistration; permissions in a charter do not provide an implementation.

Discovery depths dispatch analyst only (quick), designer then analyst (standard), or designer, challenger, experimenter then analyst (deep). Only the analyst writes a brief. SquadDiscoveryFindings binds its chosen direction to an actual host answer and retains discarded options. SquadIntakeFindings requires all five dimensions, exact source hashes, stable gaps, human questions and explicit non-blocking assumptions. SquadCouncilFindings requires role-attributed issues and checkable conditions with dependencies and source evidence. list_gate_inputs exposes exact current sources to validators. Returned prose or a verdict/count alone cannot authorize later work.

options.Tools.Add(new SquadToolRegistration(

    "edit",                      // A permission allowed by the role's charter.

The evidence contract

  • OutputEvidence is Func<object?, SquadToolOutput>, called on the actual returned function result. It must attest only successful outputs, not model arguments or intended effects.
  • SquadToolOutput(ProjectPaths, Receipt, Status) lists actual outputs and a host result status. Status defaults to Succeeded for compatible hosts; return Failed or DryRun for non-applied work. The completed call remains visible in Effects, but has no applied output evidence and cannot complete delivery. The host must truthfully attest its real outcome.
  • Host effectful integrations need actual tools, explicit approvals, successful results, and honest output evidence. A call receipt without required output evidence does not complete an effect-producing role.
  • RequireOutputForCompletion defaults to false. Set true when a host-specific producing role must demonstrate its configured effect. Optional tools do not make unrelated external actions mandatory.
  • ProjectWritePaths is a host-only argument-to-path projection checked before a writer runs. Supply contained approved paths for independent or subsequent writers; existing claims block another owner before its function is invoked. Actual output receipts must stay within the projection. The host supplies ResolveApprovedWritePaths in the example and still enforces its resource limits.
  • Output files are hashed as raw bytes, including binary files, with a 64 MiB per-file limit. Repeated approved edits within one dispatch keep all receipts and verify the last content. Only the validation-bound second draft of the same unit can supersede a prior dispatch after exact-byte archival. Unrelated ownership collisions fail closed.
  • Impact defaults to Unspecified. Noninteractive Safe writes need both ProjectWritePaths and OutputEvidence. External mutations cannot be safe. A mandatory Action still needs exact approval even with safe impact. Interactive consequential calls retain per-call approval.
  • Tools need unique names, valid effects, charter permissions, and nonempty role allowlists. Native tool names cannot be shadowed. Enforce path/resource/tenant limits inside every host function; never mutate the Scribe's state or .git.

Register an exact released script

SquadSkillScriptBinding.Create(roots, skillName, resourcePath, executorBinding) resolves an actual canonical resource and records release provenance, raw skill/script digests and a non-secret executor revision. Supply it as SquadToolRegistration.SkillScript, with the existing permission, role, effect, impact, action and output extractor. ProjectReadPaths is mandatory, including an explicit empty scope; writes also need ProjectWritePaths. Original input bytes and exact artifacts are verified before execution and after approval. Changed scopes, command builders or executors require a changed binding and cannot resume an old run.

load_skill advertises only registered script paths and schemas. MAF run_skill_script takes skillName, scriptName and an arguments object. APM directory names, resource text, guessed aliases and notification delivery do not grant authority. The registered function is not exposed through a second direct entry point. Coordinator scope cannot run specialist scripts. Private native state and unapproved sibling inputs are denied; deterministic Scribe/Consumption results and GetModelRoutingChoicesAsync replace Copilot-schema Squad scripts.

SquadProcessExecutor is a working bounded reference, not a shell or sandbox. The host fixes an absolute executable, argument builder, working root, explicit environment allowlist, timeout (at most ten minutes), output bound and declared paths. It uses separate argument-list values, closes stdin, terminates the actual process tree on cancellation/timeout and publishes stdout files only after success. A nonzero exit is Failed; changed partial outputs require reconciliation. Local outputs are hashed as exact bytes. Hosts must prevent undeclared resource access or detached children using reviewed scripts and OS/container isolation.

SquadToolOutput.ReceiptKind defaults to HostObservation for compatible hosts. The process reference returns Process; exit/stream digests cannot prove external retrieval or mutation. Retrieval, deployment, export or tracker connectors must verify their real provider/resource postconditions and supply reconciliation. Existing specific approvals and uncertain-effect checkpoints apply in every mode. Actual source revisions preserve original bytes and immutable effects through the same bounded validation authority.

The runtime does not dispose supplied functions/executors/clients. Each invocation disposes its process. An optional caller-owned ActivitySource emits run.skill_script without private arguments, paths, stdout/stderr or environment attributes; the host configures resource attributes and exporters. Captured output remains protected host/case data, not public notification or CI content. DI and live-run data configuration cannot install an executable or a delegate.

Treat status as part of the API

SquadRunResult contains RunId, Status, ResponseText, Evidence, Scope, FailureClass, Diagnostics and Effects. A non-success result may contain useful, verified partial work. Effects records completed consequential calls without claiming their owning dispatch finished. There is no separate Partial status enum.

StatusMeaning and host action
CompletedDelivery produced verified research, plan, output, and review with no reported blockers. Not deployed, released, or independently host-validated.
ResearchCompletedFocused research completed. No production claim.
PlanCompletedFocused plan completed, including applicable gates. No implementation claim.
ReviewCompletedFocused review of supplied targets completed. Not a new delivery.
ArtifactCompletedOnly the named producer stage repaired its actual artifact. Not a full inner delivery or release. The federation still verifies its handoff and consumer.
ApprovalRequiredA callback or exact authenticated durable response is missing. Inspect pending metadata, submit/poll the real response and explicitly resume the same run; do not start a replacement request.
ApprovalDeniedThe host declined. Do not retry the action as if it had been approved.
InputRequiredA host answer or existing review target is missing. Obtain the real input; do not invent it.
BlockedMissing role, failed gate, safety finding, unmet output contract, or another unmet precondition. Inspect response and evidence.
UnsupportedThe request requires an unimplemented mode or capability. Narrow the scope or implement the missing host/runtime feature explicitly.

Cancellation and timeout save the active run as failed with partial evidence, then rethrow OperationCanceledException. Acquisition, invalid options, state mismatch, and lock errors can also throw before the execution result handler. Host code must handle exceptions as well as result statuses.

What a dispatch record proves

SquadDispatchEvidence records dispatch ID, stage, role, agent, artifact path/hash, history path, summary, verdict, risk, blocking issues, model identity/source/tier, and provider-reported tokens. It may also contain companion artifacts, executed-host-tool receipts, and a structured return.

EvidenceKind is Artifact or StructuredReturn. For a return-only role, the primary path is a deterministic Scribe receipt, not a fabricated agent-authored document. Tool execution records contain name, effect, argument hash, outputs, and receipt. Unknown tokens, model identities, costs, and credits stay unknown; they are not recorded as zero or inferred from a tier.

SquadReports.DocumentAsync searches verified native projections and, when explicitly permitted, local source excerpts. GovernanceAsync renders seven fixed governance sections and six header metrics. Neither helper calls a model, initializes state, repairs a ledger, records an approval, or writes dispatch history. Create the reader directly, or use CreateReports(configuration) on SquadRuntime, SquadFederation or the DI SquadRuntimeFactory. The factory does not require an IChatClient for this path.

Natural-language requests and Watch opt-ins cannot grant disclosure permission. Protected human/effect payloads, sessions, original Watch inputs, lifecycle images and migration archives are never export sources.

Documents return Path, actual Format, requested format, explicit Fallback/Diagnostic, source paths/hashes and OpenQuestions. Focused extracts cite actual files; an unsupported inference is an open question, not a generated fact. Defaults are docs/squad-document-YYYY-MM-DD.md and docs/squad-governance-report-YYYY-MM-DD.html. Formats md and html are built in; absent pdf/docx capability or an unrecognized format explicitly falls back to real Markdown with a .md extension. An existing target is not overwritten. URLs, UNC/shared drives, traversal and native/repository protected targets are refused. Absolute paths must stay in the host-authorized local output directory.

SquadLocalDocumentRenderer is an optional credential-free .NET reference: real OOXML Word paragraphs/styles/tables and paginated WinAnsi PDF, not renamed Markdown. Unicode outside its PDF font produces an explicit Markdown fallback; Word retains Unicode, or the host can register a Unicode-capable local ISquadDocumentRenderer. A renderer receives authorized in-memory content and must return actual bytes bound to the original input hash. It receives no state paths or credentials. Custom renderer isolation and network/disclosure restrictions remain host-owned. Broken bytes or failures are errors, not claimed success.

Governance accepts all, 30d and 7d with inclusive UTC timestamp boundaries. The six metrics are Coordination Turns, Role Dispatches, Est. Cost, Total Tokens, Human Gates Fired and Escalations. Turns mean recorded coordinator invocations; dispatches mean actual role history entries. Original provider charges are summed once, including real coordinator overhead, without counting reservations, hub summaries, reused handoffs or deterministic Scribe/Watch work again. Unknown totals remain unknown with known partial sums; calibration is annotated. Native test/deployment counts without independent postconditions stay unproven. Empty sections remain visible. HTML has inline theme/styles and no external resources.

Snapshots verify original history and current source hashes without repair. A busy writer, partial state, corrupt history or a source changed during rendering stops the export. Current output drift is disclosed as historical activity without claiming current delivery. Squad selects a federation member; omission aggregates explicitly authorized members. The selected-member path reads no hub/sibling files, resolves sealed historical paths inside that member, and leaves shared project documents outside the search. Wider authorized federation reports can attribute shared outputs to their recorded owner. Single-squad selectors are ignored. All output defaults remain at project-level docs, never a member state tree.

Persistence has an owner

The deterministic native Scribe owns SquadRoot, including state.json, native.lock, roster/routing records, decisions, notifications, consumption, dispatch histories, structured returns and protected effect payloads. Native v2 stores release/root-bound checkpoints, actual MAF sessions, confirmed answers, input hashes, completed stage identities, exact effect digests and cumulative execution budgets. Authorized private case facts may persist inside protected host-controlled case storage; credentials and transport secrets remain host-owned.

Each dispatch owns its session, tools and artifact allocations. Independent council results are committed in deterministic dispatch order after the parallel calls settle. Valid concrete agent names, including capitalization and spaces, are retained in history filenames; invalid or colliding names are rejected, not hashed away. Private sessions and another active owner's outputs are not ordinary dispatch inputs.

ReconcileEvidenceAsync() checks full recorded history, exact append-only bytes/order and session/checkpoint bindings, with at most one deterministic correction pass. LedgerOnly defects warn without blocking evidence barriers or parallel dispatch; HistoryIntegrity defects stop dependent work. An exact pending append can be completed once without overwriting prior bytes or replaying an action. Native Scribe operations use no model tokens; actual coordinator/provider calls are accounted separately and unknown model costs remain unknown.

  • Turns serialize within one runtime. An exclusive per-root file lock prevents simultaneous native state writers; it is not a distributed scheduler. Atomic snapshot replacement is verified and bounded transient Windows sharing contention is logged and retried without replaying any host action.
  • Do not put horizontal replicas on the same root and assume coordination, failover, or shared-filesystem lock semantics will work. Route each root to one active owner.
  • Do not edit state or invent receipts through host tools. Methodology outputs are allocated and checked; named writer files and writer-owned areas are protected without prohibiting member-local plans and research.
  • Native state is distinct from Copilot state. Completed native v1 state at its original root can migrate only with AllowNativeV1Migration and a separate StateMigration approval. Original state bytes are backed up; decisions, histories, consumption, sessions, outcomes and extension fields are preserved. Interrupted v1 work is not automatically resumed.
  • A changed release, fingerprint, roster/root binding, host effect contract or execution limits cannot silently resume an old run. Preserve the original setup or perform separately reviewed migration/reconciliation.
  • Use ResumeAsync(runId) for a suspended v2 run. Completed stages are verified and reused; a new request is blocked while that run is active. An uncertain consequential effect returns ReconciliationRequired. Register a truthful host ReconcileAsync, call the runtime's ReconcileAsync(runId), then resume explicitly. A verified protected result can satisfy the same tool call without executing it twice.
  • Member reads are limited to their own root and exact read-only handoff files. Untrusted routed text cannot grant sibling discovery. The federation coordinator alone enumerates current producer artifacts and records verified dependency transfers; consumers never write the producer's tree. Meta transitions stay non-pipelined and shared repository outputs retain durable member ownership.

When the run stops, keep the boundary

APM not found, GitHub 403/429, or acquisition fails

Verify Git and APM on PATH, the tested APM version, outbound access, and rate-limit diagnostics. For authentication, supply an appropriately scoped host HTTP client. A pinned tag still needs release API access; choose a verified installed-directory source for disconnected loading. Do not switch to main as a workaround.

Off-roster intake-validator or a missing council seat

Inspect the exact release roster and the required concrete agent. The native gate can propose a persistent RosterUpdate extension without rewriting previous evidence. Declining intake coverage stops; declining a council records only a scoped council waiver. Missing installed resources still block rather than inventing a substitute. Retain the returned RosterConfiguration when recreating the host; never delete state to force a reseed.

ApprovalRequired, ApprovalDenied, or InputRequired

Wire the missing human callback, respect a denial, or provide the requested input. Inspect routing completeness and focused-review targets. The library has no remote approval endpoint and does not interpret a file containing “approved” as consent.

Session fingerprint, release, or schema mismatch

Restore the original release, full artifact tree, and confirmed configuration. Do not mutate state.json, copy Copilot state into place, or overwrite receipts. Back up and use an isolated project while designing any explicit migration.

Lock contention or an interrupted run

Find the owner of the project and wait for its run to finish. Stop it through its normal cancellation/lifecycle path if appropriate. A lock file's presence does not mean it is stale; exclusivity is held by the open file handle. Do not delete live lock files or run replicas concurrently.

“Completed” prose, but no accepted output evidence

Inspect the actual result status, dispatch record, output allocations, receipts, and hashes. Register the necessary host executor and truthful evidence extractor. A prose claim about edits, tests, deployment, or a deck cannot substitute for real execution. Never fabricate success to satisfy the gate.

LimitReached, cancellation, or model/tool failure

Inspect partial evidence before resubmitting. Split oversized work into bounded interactive turns. Adjust explicit budgets only after understanding call volume. Do not blindly retry external operations: use host-owned idempotency and reconcile actual effects. Check that your selected model implements reliable tool calls.
